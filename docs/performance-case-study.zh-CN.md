# 性能案例：住宅出口与高速 VPS 分流

这是一份经过脱敏的真实部署记录，用来说明 RoutePilot 解决了什么问题。它不是任何线路的速度承诺。

## 原始问题

原链路把所有流量都送进同一条路径：

```text
Windows → Reality TCP 443 → VPS → 住宅代理 → Internet
```

这能让网站看到住宅出口，但视频、软件包和其他大文件也必须经过住宅供应商。住宅代理套餐、上游负载、跨网距离和二次转发都可能成为瓶颈。这里受限的不是“IP 地址”本身，而是提供这个出口的服务和传输路径。

## 改造后的路径

部署增加了一个独立的高速通道：

```text
受保护请求：Windows → Reality TCP 443 → VPS → 住宅代理 → Internet
大流量请求：Windows → Hysteria 2 UDP 443 → VPS → Internet
```

服务端 TCP 443 与 UDP 443 属于不同协议，可以同时监听。Edge 中的 PAC 按域名选择本地代理：YouTube 页面与 Google 账号请求保留在住宅路径，`googlevideo.com` 视频载荷进入 VPS 高速路径。

## 测试条件

- 日期：2026-08-02
- 测试对象：同一个 Cloudflare 5 MB 文件
- 对比方式：单连接多次测试取中位数；另做四路并发汇总测试
- Hysteria 2 最终带宽参数：下行 80 Mbps，上行 20 Mbps
- 所有公网地址、认证信息与供应商账号均未公开

## 完整数据

| 通道 | 单连接中位速度 | 四路并发总速度 |
|---|---:|---:|
| 原 Reality + 住宅转发路径 | 7.02 Mbps | 24.02 Mbps |
| Hysteria 2，30 Mbps 参数 | 19.16 Mbps | 24.64 Mbps |
| Hysteria 2，50 Mbps 参数 | 27.84 Mbps | 37.28 Mbps |
| Hysteria 2，最终 80 Mbps 参数 | **37.93 Mbps** | **57.34 Mbps** |

同口径比较：最终单连接约为原来的 5.4 倍，四路并发总速度约为原来的 2.4 倍。

## 单位为什么容易说错？

- `Mbps`：兆比特每秒，网络带宽通常使用这个单位。
- `MB/s`：兆字节每秒，下载软件常用这个单位。
- 1 字节等于 8 比特，所以 57.34 Mbps 理论换算约为 7.17 MB/s，未扣除协议开销。

因此不能把本次结果写成“从 7 MB/s 到 50 MB/s”。准确表述是：单连接约 7.02 Mbps 到 37.93 Mbps，四路并发最终达到 57.34 Mbps。

## 技术原理

### 1. 按请求分流，而不是切换整个节点

网页并非来自一个服务器。页面、登录接口、图片、视频切片可能使用不同域名。PAC 对每个 hostname 做确定性选择，因此同一个 Edge 窗口内可以让账号请求与视频载荷走不同出口。

### 2. 让住宅路径只承担它擅长的流量

住宅路径保留出口一致性，但不再承担视频和安装包。高速路径直接从 VPS 出口，不经过住宅代理的带宽、流量额度和额外转发限制。这是本案例提速的主要来源。

### 3. Hysteria 2 承载高速路径

Hysteria 2 基于 UDP/QUIC。在高延迟或存在丢包的网络上，它可以避免嵌套 TCP 转发常见的重传相互影响，并利用可配置的带宽参数进行拥塞控制。它不会凭空制造带宽；最终速度仍由本地网络、VPS 带宽、路径质量和目标服务器共同决定。

### 4. 受保护域名安全失败

受保护域名的 PAC 结果只有主代理，没有 `DIRECT` 或高速代理备用项。住宅通道不可用时，请求会失败，而不是在用户不知情时换出口。高速域名同样不会回落到住宅线路，避免意外消耗住宅流量。

## 如何理解结果

这些测试证明“分开走”在该环境中显著降低了大流量传输的瓶颈，但不能证明所有用户都会获得相同倍数。距离更近的 VPS、更好的本地网络可能更快；VPS 限速、UDP 受限、目标 CDN 拥堵或线路丢包也可能让收益变小。部署后应使用相同测试对象、相同次数和相同并发度做自己的 A/B 测试。
